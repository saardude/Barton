# Data: record shape and heuristics

The dataset lives in `australia/data/`. Everything is written by `scraper/src/build.js` from the
parsed pages (`scraper/raw/afs/records.json`, not committed) and the newspaper gazetteer
(`data/newspapers.json`, committed). Output is deterministic: sorted keys, stable ids, records
sorted by page number. The JSON schemas in `data/schema/` are authoritative; `npm run validate`
in `scraper/` checks every file, and `qa/checks/data-gates.mjs` adds the cross-file gates.

## Files

| File | What |
| --- | --- |
| `songs.json` | one record per song or poem page (`afs-001` ... `afs-1100`, plus `afs-052a`) |
| `places.json` | the place tree: `au` > `au/nsw` > `au/nsw/kiama`; foreign papers as `nz`, `uk`, `us`; counts per node |
| `facets.json` | value -> count for decade, year, kind, state, town, newspaper, songbook, singer, collector, author, image roles, MIDI, MP3, year source |
| `sources.json` | the site, the songbook bibliography (`book-001` ...), the articles index, and every newspaper cited with counts, years, state hints and its resolved place |
| `newspapers.json` | the gazetteer: newspaper key -> town, state, coordinates, Wikidata / GeoNames ids, confidence; generated by `geo/resolve-newspapers.mjs` |
| `newspapers-overrides.json` | curated entries that win over Wikidata and GeoNames (generic titles, papers with the same name in several cities) |

## A record

```
id            afs-999                       'afs-' + the page number on folkstream.com
source        site, siteName, siteId ('999'), url, fetchedAt
title         "A Song of The Surf Club"     the page <title> (index title if the two disagree and the index agrees with <em>)
titleRaw      "A Song of The Surf Club (1929)"
titleAlt      other titles the contents page lists the same page under
kind          song | poem | unknown         song: notation, MIDI, MP3 or a tune mentioned; poem: 'poem', 'ode', 'verses' ... in title or notes
year          { value, approx, from: title|index|newspaper|notes, decade }
author        { name, raw, signature }      'written by X', a 'By X' line, or a one-line signature after the last stanza (name before the comma)
text          { incipit, stanzas[][], lineCount, wordCount }
notes         { text, links[{text, href}] }  Mark Gregory's notes as plain text with paragraph breaks
provenance    newspaper: { title, key, troveArticleId, troveUrl, date{year,month,day,raw}, page, stateHint, context }
              songbooks[book-id], singers[], collectors[]
media         images[{url, type, role: notation|masthead, width, height}], midi[{url}], audio[{url}]
location      { basis: newspaper|newspaper-state|null, state, town, lat, lng, placeId, raw }
related       [{id, relation: variant|see|linked, title}]
themes        []   (reserved for a curated layer)
warnings      parser notes ('title from <em> ...', 'no Notes heading found')
```

## Heuristics, in one place

All in `scraper/src/normalize.js`, each with unit tests in `scraper/tests/normalize.test.js`.

- **Newspaper.** The text of the first link to a Trove article is the paper's title; failing
  that, a sentence "From the <State> newspaper <Title> <date>". The title is cleaned of a
  trailing date, page, weekday or connective. The date is the first date after the title, the
  page the first "Page n" / "p. n". The words before "newspaper" are the state hint, folded to
  a state code with typo-tolerant patterns.
- **Place.** The paper's key looks up the gazetteer. An entry with `variants` (one per state)
  is resolved by the record's state hint, else its default variant. Without a gazetteer entry
  the record sits at the state named in the notes, or nowhere.
- **Year.** Title `(1929)` or `(1860s)` (approx), else the contents page, else the newspaper
  date, else a year in the notes next to "published", "printed", "collected", "written".
- **People.** Singers: "from the singing of X", "sung by X", "collected from X", "collected by
  Y from X". Collectors: "collected by X", "recorded by X". Author: "written by X". Names allow
  initials ("A.L.Lloyd", "C. R. E. Grainger") and stop at a preposition.
- **Images.** `scraper/src/images.js` reads the first bytes of every image for its size: wide and
  under 200 px tall is a newspaper masthead, anything else notation. Without a probe, GIFs are
  notation and PNGs on a Trove-sourced page are mastheads.
- **Songbooks.** A bibliography title of ten characters or more found in the notes (folded).
- **Related.** Links to other record pages in the notes ("linked"), "See 'Title'" ("see"), and
  records whose title differs only by a trailing number ("variant").

## Gazetteer

`geo/resolve-newspapers.mjs` resolves the titles in `sources.json` in three passes:
curated overrides; Wikidata (every item with a Trove newspaper ID or typed as an Australian or
New Zealand newspaper, with place of publication, coordinates and state; a title shared by
several papers becomes an entry with variants); a town name in the title, looked up in the
GeoNames populated places of Australia, preferring the state the notes name. Each entry carries
a `confidence` (curated, high, medium, low) and a `note`. Re-run it after a crawl that adds
titles; it prints the unresolved ones.
